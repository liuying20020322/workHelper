# workHelper

个人本地求职投递管理。第一版五个阶段已完成：投递管理、流程安排、首页提醒、面经复盘，以及备份恢复和本地运行交付。

## 已实现

- 公司按去除首尾空格后的名称分组；每次投递使用独立 ID，相同公司、岗位也允许多次投递。
- 公司、岗位必填，投递时间默认当前业务时间，其余信息可补充。编辑不会修改创建时间。
- 公司 / 岗位 / 地点搜索，按投递时间倒序排列；公司和岗位分别展开。
- 弹窗新增 / 编辑、删除确认、空状态、加载和错误提示；服务保存失败保留表单。
- 岗位下添加、编辑、删除流程，支持定时安排、截止任务、仅记录阶段；测评和笔试均可选择时间方式。
- 安排支持完成、取消、恢复待完成和改期。仅记录阶段明确显示“未设置提醒”。
- 当前阶段自动计算：普通阶段取最高进度；Offer、未通过、已撤回优先，按阶段发生时间选择最新结果（同一时间取较大 ID）。
- 取消安排保留招聘阶段；删除流程重算阶段。补录早期流程不会导致进度倒退，标记完成不会新增下一阶段。
- 一面、二面、三面支持自定义轮次名称，进度仍由所选阶段决定，例如“HR 面”可归属于二面。
- MySQL 持久化、Flyway 版本化迁移、健康检查、统一配置、前后端打包成单个 JAR。

首页支持近三天、全部待办、已完成与独立逾期列表；面试流程支持总结及问答；顶部辅助入口提供备份与恢复，主导航包含首页、投递管理和看过未投。

## 环境

- Java 21，MySQL 8.0+（本次真实联调版本为 8.0.31）。
- 构建需要 Node.js 22.12+ 或 24，以及 npm；日常运行只需要 Java 和 MySQL。
- 保留项目原有 Spring Boot 4.1.1，使用 Spring JDBC、Flyway；Vue 3、TypeScript、Vite、Element Plus、Vue Router。前端精确依赖由 `package-lock.json` 锁定。

## 首次运行

1. 启动自己的 MySQL 服务，用管理工具预先建立空数据库（应用不会创建数据库）：

   ```sql
   CREATE DATABASE work_helper CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_as_cs;
   ```

   配置一个有此数据库建表、索引和数据读写权限的本地账号。无需授予创建其他数据库权限。

2. 编辑 `src/main/resources/application.yml`，直接填写数据库地址、用户名和密码。所有运行配置统一在此文件中。
3. 双击或在终端运行 `build.bat`，构建前端并执行后端测试，生成 `target/workHelper.jar`。
4. 双击 `start.bat`。脚本检查 Java 21、JAR、配置和端口，等待数据库健康检查成功，再自动打开浏览器。默认地址为 `http://127.0.0.1:8080/#/home`。
5. 保留启动控制台，使用 Ctrl+C 停止服务。关闭浏览器不会停止服务。启动及运行日志保留在 `logs/`。

已经启动时再次运行脚本会打开已有页面。端口被其他程序占用会明确报错；连接失败请检查 MySQL 服务、数据库是否存在及账号权限；启动超过 90 秒会提示并停止本次进程。脚本不安装或管理 MySQL 服务。

`build.bat` 使用 Maven Wrapper；首次需要网络下载 Maven 和依赖。已安装 Maven 时也可依次执行 `npm ci`、`npm run build`（在 frontend 目录）和 `mvn package`（项目根目录）。

## 配置

| 配置 | 默认值 |
| --- | --- |
| `spring.datasource.url` | MySQL 地址，默认 `127.0.0.1:3306/work_helper` |
| `spring.datasource.username` | 填写自己的 MySQL 用户名 |
| `spring.datasource.password` | 填写自己的 MySQL 密码，保留引号 |
| `server.port` | `8080`（整数） |
| `app.time-zone` | `Asia/Shanghai` |

只需编辑 `src/main/resources/application.yml`。启动脚本和 IDE 使用这份运行配置。`src/test/resources/application.yml` 仅用于自动化测试的内存数据库，不用于日常启动。

配置采用 YAML，使用空格缩进，不使用 Tab。启动脚本读取 `server:` 下缩进两个空格的 `port: 8080`。默认仅监听 `127.0.0.1`。如需修改数据库主机、端口或库名，修改 `spring.datasource.url` 中对应部分；修改业务时区时同步修改 URL 中的 `connectionTimeZone`。

所有业务时间是所配置时区的本地时间，数据库采用 `DATETIME(6)`，API 使用无偏移的 ISO 日期时间（例如 `2026-10-07T14:30:00`）。前端通过 `/api/info` 获取业务时区。无需导入 MySQL 命名时区表。已有记录不会随时区配置变更自动换算。

构建不会修改源码配置，也不清理业务数据库；不要把日常数据库的数据目录放入项目 `target/`。首次启动 Flyway 创建业务表及迁移历史；已有数据库自动执行尚未执行的迁移。V2 增加流程，V3 增加面经，V4 增加备份恢复的写入协调记录，V5 增加看过未投记录，保留原有业务数据。不要修改已执行的迁移文件，也不要让新旧版本同时操作同一数据库。

## 开发

后端：在项目根目录执行 `mvnw.cmd spring-boot:run`（自动读取 `src/main/resources/application.yml`）。

前端：在 `frontend` 执行 `npm ci`、`npm run dev`，访问 `http://127.0.0.1:5173`。默认代理 API 至 8080；修改后端端口时，在 PowerShell 设置 `$env:API_TARGET='http://127.0.0.1:你的端口'` 后启动前端。

Vue 使用 hash 路由，刷新或直接访问页面无需服务器路由回退。Maven 会把 `frontend/dist` 复制到 JAR 的静态资源目录；页面改动后需重新构建前端。

## 首页提醒

- 默认进入首页，近期待办按业务时区的今天、明天、后天三个自然日计算，不按未来 72 小时计算。
- 定时安排按开始时间，截止任务按截止时间升序排列；同一时间按流程 ID 稳定排序。
- 已逾期且待完成的安排独立展示；跨日且仍在进行的定时安排继续保留。
- 截止任务超过截止时间算逾期；定时安排有结束时间时超过结束时间才算逾期，没有结束时间则超过开始时间算逾期。恰好等于边界时不算逾期。
- “全部待办”包含三天以外的未来安排；“已完成”只展示设置了时间的已完成安排。已取消、仅记录阶段均不进入提醒。
- 可以直接标记完成、编辑/改期（含取消、恢复待完成），也可以跳转投递并自动展开、高亮对应流程。
- 首页与投递页使用同一流程接口和编辑组件，无独立日程表。保存失败保留表单，列表读取失败显示错误与重试入口。
- 打开首页、窗口恢复焦点、切回标签及跨天时重新查询；页面可见时每 30 秒刷新一次，离开页面会清理定时器。程序退出后不提供提醒。

## 面经复盘

- 在投递下的一面、二面、三面流程点击“记录面经”；已有总结或问答时显示“查看面经”。不要求安排已完成，也不增加主导航菜单。
- 详情显示所属公司、岗位、工作地点、轮次和时间；返回时展开并定位原流程。
- 总结和问答通过弹窗编辑，点击“应用修改”返回详情，再点击“保存面经”将整轮总结、增删和排序一次保存。上移/下移调整问答顺序。
- 问题必填，回答与复盘可以留空；纯文本保留换行。每轮最多 200 条，问题最多 20000 字，回答、复盘和总结分别最多 50000 字。
- 保存失败保留输入，未保存离开有提示。同一轮多页面编辑使用版本校验，旧版本保存返回 409；先复制需要保留的输入，再重新载入并核对。
- 有面经的流程不能改成非面试阶段；清空总结和问答并保存后才可改。面试阶段之间切换保留面经，取消安排也保留面经。
- 删除流程连带删除该轮问答，删除投递连带删除全部流程和问答，操作前均有确认提示。

## 备份与恢复

1. 点击顶部“备份与恢复”→“下载 JSON 备份”，确认浏览器下载完成，将文件另存到可靠位置。
2. 恢复时选择 JSON 文件并点击“校验备份”，查看当前与恢复后的投递、流程、问答数量。校验不会修改数据库。
3. 保存当前及其他标签页中的编辑内容，关闭其他编辑页面；输入“替换全部数据”，再点击“确认替换并恢复”。这是全量替换，不是追加或合并；空备份会清空业务数据，界面会额外提示。
4. 覆盖前自动保存当前完整数据到项目根目录 `backups/`，写入成功后才执行替换。成功后当前页面重新读取数据；恢复失败则事务回滚，自动备份仍保留。
5. 如需撤回恢复，从弹窗下方“恢复前自动备份”下载对应文件，再按相同步骤恢复。也可以直接从本地 `backups/` 取文件。文件名中的时间为 UTC（Z）。

备份格式为 `workHelper-backup`，当前版本 `2`，兼容导入版本 `1`。包含全部投递、看过未投记录、流程安排、面试总结、问答、关联编号、排序及创建/更新时间，不包含数据库密码、运行配置和 Flyway 历史。迁移到另一台电脑时先建立空库并运行应用，再导入备份；数据库主机与账号仍在该电脑的 YAML 中填写。

- 文件最大 32 MB，每类最多十万条记录；导出和恢复均检查上限，超限时明确停止，不截断数据。每轮问答和文本长度沿用录入限制。
- 严格检查 JSON、版本、业务时区、字段、编号重复、关联关系、安排时间和问答排序。业务时区不同会拒绝恢复，不自动换算历史时间。
- 校验后业务数据或备份文件变化会要求重新校验。所有业务写入、导出与恢复通过同一数据库锁协调，恢复在单个事务中完成，不使用会隐式提交的清空表语句。
- 恢复保留业务 ID、时间和问答顺序，重新计算投递阶段、面经标识等派生数据；面经编辑版本会递增，防止旧页面覆盖恢复后的内容。已有自增序列不会重置。
- 自动备份目录已加入 Git 忽略，不在 `target/` 中，重新构建不会删除；文件不自动清理，请定期另存并自行整理。自动备份不能代替异盘备份。
- 自动备份写入失败（如目录无权限、磁盘空间不足）时不替换数据。若网络中断或请求超时，请先刷新核对实际结果，再决定是否重新恢复。

## 更新与运行排查

更新前导出备份，使用 Ctrl+C 停止应用，再运行 `build.bat`，最后 `start.bat`。构建发现 JAR 正被使用时，会在安装依赖和清理构建目录之前停止并提示关闭服务。保留 `src/main/resources/application.yml` 的实际配置和 `backups/`，无需重新创建业务数据库。

在已安装 Java 21、MySQL 的电脑上日常运行，至少保留 `start.bat`、`scripts/start.ps1`、`target/workHelper.jar`、`src/main/resources/application.yml` 及需要保留的 `backups/`，目录层级不变。无需安装 Node.js；修改源码并重新构建时才需要 Node.js/npm。

| 现象 | 处理方式 |
| --- | --- |
| 提示 Java 版本不符 | 将 Java 21 加入 PATH，重新打开终端后运行 `java -version` |
| 缺少 JAR | 在开发电脑运行 `build.bat`，复制生成的完整 JAR |
| 端口已占用 | 停止占用端口的旧服务，或修改 YAML 中 `server.port`；不要重复启动多个版本 |
| 数据库连接失败 | 核对 MySQL 已启动、数据库已创建、地址和账号密码正确；查看 `logs/` 中该次启动日志 |
| 自动备份写入失败 | 检查项目 `backups/` 的写入权限和磁盘空间，解决后重新校验 |
| 恢复校验提示数据已变化 | 关闭其他编辑页面，重新校验并核对数量，再确认恢复 |

## API

| 方法 | 地址 | 功能 |
| --- | --- | --- |
| GET | `/api/applications?search=&stage=` | 投递列表、文字搜索、阶段筛选 |
| GET | `/api/applications/{id}` | 单条详情 |
| POST | `/api/applications` | 新增，返回 201 |
| PUT | `/api/applications/{id}` | 修改 |
| DELETE | `/api/applications/{id}` | 删除，返回 204 |
| GET | `/api/reminders?view=RECENT` | 近期待办与逾期；可选 `ALL` / `COMPLETED` |
| GET | `/api/info` | 应用标识、业务时区、当前业务时间 |
| GET | `/actuator/health` | 包含数据库连通性的健康检查 |
| GET | `/api/backups` | 下载当前完整 JSON 备份 |
| POST | `/api/backups/preview` | 校验备份，返回文件摘要、当前修订号及数量对比 |
| POST | `/api/backups/restore` | 自动备份当前数据后全量替换 |
| GET | `/api/backups/safety` | 列出本地恢复前自动备份 |
| GET | `/api/backups/safety/{name}` | 下载指定自动备份，限制为服务生成的文件名 |

备份校验/恢复直接提交原始 JSON 文件字节（`Content-Type: application/json`）。恢复请求须携带预览返回的 `X-Backup-Revision`、`X-Backup-SHA256`，以及 `X-Backup-Confirmation: REPLACE_ALL`。校验失败返回 400、超过文件大小限制返回 413、预览过期或文件变化返回 409。

请求字段：`companyName`、`positionName`、`location`、`requirements`、`appliedAt`、`channel`、`jobUrl`、`notes`。`currentStage` 只读，不从请求写入。支持的筛选阶段见 `frontend/src/api.ts`。无效输入返回 400、不存在返回 404、数据库异常返回 503，错误体统一含 `message`。

采用物理删除，需前端确认。删除投递会通过外键级联删除流程、安排及问答。流程写入与投递阶段重算位于同一事务，并锁定所属投递以避免并发重算丢失。面经保存使用相同父记录锁，与流程修改、删除保持一致。

流程 API（`{appId}` 为所属投递，所有操作校验归属关系）：

| 方法 | 地址 | 功能 |
| --- | --- | --- |
| GET / POST | `/api/applications/{appId}/processes` | 查询列表 / 新增流程 |
| GET / PUT / DELETE | `/api/applications/{appId}/processes/{id}` | 查询 / 编辑 / 删除流程 |
| PATCH | `/api/applications/{appId}/processes/{id}/status` | 设置 `PENDING`、`COMPLETED` 或 `CANCELLED` |
| GET / PUT | `/api/applications/{appId}/processes/{id}/interview` | 读取 / 原子保存整轮面经 |

面经 PUT 字段：`version`（GET 返回的编辑版本）、`summary`、`questions` 数组。每条包含已有问答 `id`（新增省略）、`question`、`answer`、`review`；数组顺序即保存顺序，未包含的旧问答会删除。服务端校验投递、流程及问答归属，拒绝重复 ID 和过期版本。

流程字段：`stage`、`roundName`、`timeMode`、`startAt`、`endAt`、`deadlineAt`、`status`、`location`、`notes`、`occurredAt`。

- `SCHEDULED`：开始时间必填，结束不能早于开始。
- `DEADLINE`：截止时间必填，可选开始时间不能晚于截止。
- `RECORD_ONLY`：不设置安排时间；切换到此模式保存时清除旧安排时间。
- `occurredAt` 用于补录及结果阶段排序；未提供时新增默认业务当前时间，编辑保留原值。
- 流程列表按发生时间从新到旧排列；最高进度计算不依赖列表顺序或完成状态。

## 看过未投

- 顶部“看过未投”菜单独立管理记录；公司名称、未投原因、看过日期必填，日期默认业务时区的今天，可修改补录。
- 原因下拉单选：要求英语四级、要求英语六级、没有合适岗位、学历不符合、经验不符合、工作地点不合适、其他。选择其他时必须填写具体原因（最多1000字）。
- 同一公司保留一条记录，公司名称去除首尾空白；支持新增、编辑、删除。公司名称建议与投递记录保持一致，不自动识别简称或别名。
- 公司名称搜索与看过月份组合筛选，月份为空表示全部月份；按看过日期倒序排列，同日按编号倒序。重置清空两个筛选条件。
- 新增投递保存成功后，精确匹配同名的未投记录，展示看过日期及原因，选择“删除未投记录”或“暂时保留”。投递保存失败不会删除记录，删除失败也不会撤销已保存的投递。
- 导出和恢复包含未投记录。旧版备份没有未投记录，恢复预览显示为0；全量恢复旧备份会清空现有未投记录，恢复前自动备份仍保存这些记录。
- 接口：`GET /api/unapplied-companies?search=&month=YYYY-MM`、`POST /api/unapplied-companies`、`PUT /api/unapplied-companies/{id}`、`DELETE /api/unapplied-companies/{id}`。
